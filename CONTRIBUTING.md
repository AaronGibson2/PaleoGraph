# Contributing

Use [README](README.md) for local commands. Preserve stable source identities,
retained revisions, typed provenance, geological uncertainty and the [glossary](CONTEXT.md).
Review scientific semantics and public API/schema changes carefully.

Use strict TypeScript, SQLAlchemy 2 and typed Python boundaries; run Ruff, mypy,
frontend lint/typecheck/tests/build and the relevant disposable integration/browser
scripts. Commit lockfile changes when dependencies change. Never commit credentials,
raw datasets, node_modules or virtual environments. Only Alembic owns schema changes;
never call create_all as setup. Review autogenerated migrations and exclude PostGIS-owned tables.

Synthetic rows belong only to isolated automated fixtures. `scripts/test_db.py` and
`scripts/test_browser.py` own separate ephemeral PostGIS projects. Never set
TEST_DATABASE_URL to valuable data or import dense browser fixtures into development.
Ordinary pytest skips database integration. Browser regression tests stub cartography
only; scientific API, database, workers and interaction remain real. Supplement UI
changes with inspected unmocked screenshots. Document checks actually run, failures
and limitations; remote CI must pass before merge.

Phase 3.5 ends at the source-grounded discovery implemented here. Do not incidentally
add second-source ingestion, reconciliation, auth, AI, external search/graph services
or deployment. Publication relationships require explicit source evidence, not a
nearby label or a guessed DOI. Changes to age mapping require an attributed versioned
policy and retained interpretation history. Full imports require adequate disk/WAL/
backup headroom and measured scale validation before changing the default scope.
